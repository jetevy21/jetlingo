JetLingo — Manuel Administrateur

Guide complet pour déployer, configurer et maintenir l'application d'apprentissage linguistique par IA.

📄 Version 1.0 📅 Juillet 2026 🔧 Dernière mise à jour : 21/07/2026

📖 Introduction

Ce manuel s'adresse aux administrateurs et développeurs chargés de déployer, configurer et maintenir JetLingo, une application d'apprentissage des langues propulsée par l'intelligence artificielle.

JetLingo utilise des avatars IA conversationnels pour offrir une expérience d'apprentissage immersive et personnalisée. Ce document couvre l'ensemble des aspects techniques nécessaires au bon fonctionnement de l'application en environnement de production.

ℹ️
Pour le manuel utilisateur, consultez le document manuel-utilisateur.html disponible dans le même dossier.

⚙️ Prérequis

Avant de commencer l'installation, assurez-vous que votre environnement dispose des éléments suivants :

Technologie Version requise Notes
Node.js 18+ Vérifier avec node -v
PostgreSQL 14+ Base de données principale
Redis — Optionnel, pour le cache et les sessions
Compte OpenAI — Clé API requise pour les fonctionnalités IA
npm ou yarn npm 9+ ou yarn 1.22+ Gestionnaire de paquets

🚀 Installation

Suivez les étapes suivantes dans l'ordre pour installer et démarrer JetLingo en mode développement :

  1. Cloner le dépôt 
    git clone https://github.com/yourusername/jetlingo.git
cd jetlingo
  2. Installer les dépendances 
    npm install
  3. Copier le fichier d'environnement 
    cp apps/backend/.env.example apps/backend/.env
  4. Configurer les variables d'environnement

    Éditez le fichier apps/backend/.env avec vos paramètres. Consultez la section Configuration pour le détail de chaque variable.

  5. Créer l'utilisateur et la base PostgreSQL 
    psql -U postgres -c "CREATE USER jetlingo WITH PASSWORD 'JetLingo2026!';"
psql -U postgres -c "CREATE DATABASE jetlingo OWNER jetlingo;"
  6. Appliquer le schéma et charger les données 
    cd apps/backend
npx drizzle-kit push
npm run seed
cd ../..
  7. Démarrer le serveur de développement 
    npm run dev

    L'application est accessible sur http://localhost:3000 (frontend) et http://localhost:4000 (backend API).

✅
Si toutes les étapes sont correctement exécutées, le serveur backend démarre et la base de données contient 50+ avatars et 40+ leçons.

🔧 Configuration

4.1 — Variables d'environnement

Le fichier apps/backend/.env contient l'ensemble des paramètres de configuration :

Variable Description Exemple
DATABASE_URL Chaîne de connexion PostgreSQL postgresql://jetlingo:JetLingo2026!@localhost:5432/jetlingo
OPENAI_API_KEY Clé secrète de l'API OpenAI sk-proj-xxxxxxxxxxxx
OPENAI_MODEL Modèle IA principal pour les conversations gpt-4o
OPENAI_MAX_TOKENS Nombre maximum de tokens par réponse 512
OPENAI_TEMPERATURE Créativité du modèle (0.0 à 2.0) 0.7
JWT_SECRET Secret pour la signature des tokens JWT un-secret-ultra-securise-2026
JWT_EXPIRATION Durée de validité des tokens (en secondes) 86400 (24h)
PORT Port du serveur backend 4000
REDIS_URL Connexion Redis (optionnel) redis://localhost:6379
NODE_ENV Environnement d'exécution development ou production
CORS_ORIGIN Origines autorisées (séparées par des virgules) http://localhost:3000

4.2 — Configuration OpenAI

Modèle GPT-4o

Utilisé pour les conversations avec les avatars. Coût estimé : ~$0.005 / 1K tokens input, ~$0.015 / 1K tokens output.

Modèle Whisper

Utilisé pour la reconnaissance vocale (prononciation). Coût estimé : ~$0.006 / minute audio.

Modèle TTS-1-HD

Utilisé pour la synthèse vocale des avatars. Coût estimé : ~$0.030 / 1K caractères.

⚠️
Suivez attentivement vos coûts OpenAI dans le dashboard OpenAI. Configurez un seuil d'alerte budgétaire.

4.3 — Configuration JWT

JWT_SECRET

Chiffrez une valeur aléatoire et complexe. Ne jamais commiter cette clé dans le dépôt Git. Exemple de génération :

openssl rand -base64 48

JWT_EXPIRATION

Valeur en secondes. Par défaut : 86400 (24 heures). Pour un environnement plus strict, réduisez à 3600 (1 heure) et implémentez un système de refresh token.

4.4 — Configuration CORS

CORS_ORIGIN

Liste des origines autorisées à accéder à l'API, séparées par des virgules. En production, ne jamais utiliser *. Spécifiez uniquement les domaines de votre frontend :

CORS_ORIGIN=https://jetlingo.app,https://www.jetlingo.app

4.5 — Configuration Redis

Redis (optionnel)

Redis est utilisé pour le cache des réponses IA, le rate limiting et la gestion des sessions. Si non configuré, l'application fonctionne sans Redis avec des performances réduites.

REDIS_URL=redis://localhost:6379

🗄️ Gestion de la base de données

5.1 — Commandes Drizzle

JetLingo utilise Drizzle ORM pour la gestion du schéma de la base de données. Ces commandes s'exécutent depuis apps/backend/ :

Commande Description Usage
npx drizzle-kit push Pousse le schéma vers la base de données (sans migration) Développement rapide, écrase les changements
npx drizzle-kit migrate Exécute les migrations de manière contrôlée Production, suivi de version
npx drizzle-kit generate Génère les fichiers de migration à partir du schéma Avant de commiter un changement de schéma
npx drizzle-kit studio Ouvre l'interface graphique Drizzle Studio Exploration visuelle de la base de données

5.2 — Script de seed

Le script npm run seed insère les données initiales suivantes dans la base :

50+ Avatars

Personnages IA avec des personnalités, nationalités et styles de conversation variés. Chaque avatar a un nom, une bio, un style de dialogue et un type de voix TTS assigné.

40+ Leçons

Contenus pédagogiques couvrant 6 types : conversation, grammaire, vocabulaire, prononciation, roleplay et préparation d'examen. Structurés par niveaux CEFR (A1 à C2).

1 Utilisateur démo

Compte de démonstration : demo@jetlingo.app / demo1234. Utilisable pour tester l'application sans créer de compte.

5.3 — Réinitialisation complète

Pour effectuer un reset complet de la base de données :

cd apps/backend

# Supprimer et recréer la base de données
psql -U postgres -c "DROP DATABASE jetlingo;"
psql -U postgres -c "CREATE DATABASE jetlingo OWNER jetlingo;"

# Repousser le schéma
npx drizzle-kit push

# Recharger les données
npm run seed
🚨
Attention : Cette opération supprime toutes les données existantes, y compris les comptes utilisateurs et les progrès d'apprentissage. Effectuez une sauvegarde avant d'exécuter cette commande en production.

5.4 — Sauvegarde et restauration

Sauvegarde

pg_dump -U jetlingo -d jetlingo -F c -f jetlingo_backup_$(date +%Y%m%d_%H%M%S).dump

Restauration

pg_restore -U jetlingo -d jetlingo -c jetlingo_backup_20260721_120000.dump

JetLingo utilise Fastify comme framework backend. Les logs sont configurés via :

{
  "logger": {
    "level": "info",
    "transport": {
      "target": "pino-pretty",
      "options": { "translateTime": "SYS:standard", "ignore": "pid,hostname" }
    }
  }
}
Niveau Description Quand l'utiliser
fatal Erreur critique, le processus s'arrête Erreurs non récupérables
error Erreur requête ou interne Erreurs API, échecs DB
warn Avertissement Dépréciations, seuils atteints
info Information générale Démarrage, requêtes normales
debug Détails de débogage Développement uniquement
trace Très détaillé Debug intensif

8.2 — Monitoring des appels OpenAI

Chaque appel à l'API OpenAI est loggé avec les informations suivantes :

  • Tokens input : Nombre de tokens envoyés au modèle
  • Tokens output : Nombre de tokens générés par le modèle
  • Coût estimé : Calcul automatique selon le modèle utilisé
  • Latence : Temps de réponse en millisecondes
  • Statut : Succès ou erreur (avec code d'erreur)

8.3 — Métriques à surveiller

Métrique Description Seuil d'alerte recommandé
Utilisateurs actifs Nombre d'utilisateurs connectés les 7 derniers jours < 100 en production
Sessions par jour Nombre de sessions d'apprentissage créées par jour Baisse de > 30% en une semaine
Taux de rétention Pourcentage d'utilisateurs actifs après 7 jours < 40%
Temps de réponse moyen Latence moyenne des endpoints API > 2000ms
Erreurs API Taux d'erreurs 4xx/5xx > 1% des requêtes

🔒 Sécurité

9.1 — Rotation du JWT_SECRET

⚠️
Effectuez une rotation du JWT_SECRET tous les 90 jours minimum. Lors de la rotation, tous les tokens existants seront invalidés et les utilisateurs devront se reconnecter.
# Générer un nouveau secret
NEW_SECRET=$(openssl rand -base64 48)
echo "Nouveau JWT_SECRET : $NEW_SECRET"

# Mettre à jour le fichier .env
sed -i "s/JWT_SECRET=.*/JWT_SECRET=$NEW_SECRET/" apps/backend/.env

# Redémarrer le service
pm2 restart jetlingo-api

9.2 — Gestion des clés API OpenAI

  • Ne jamais commiter les clés API dans le dépôt Git
  • Utiliser des variables d'environnement pour les stocker
  • Activer les alertes de consommation dans le dashboard OpenAI
  • Utiliser des clés séparées pour les environnements de développement et production
  • Rotation des clés tous les 6 mois

9.3 — Sauvegarde de la base de données

Configurez des sauvegardes automatiques quotidiennes :

# Crontab — sauvegarde quotidienne à 3h00
0 3 * * * pg_dump -U jetlingo -d jetlingo -F c -f /backups/jetlingo_$(date +\%Y\%m\%d).dump

9.4 — Mise à jour des dépendances

# Vérifier les vulnérabilités
npm audit

# Corriger automatiquement
npm audit fix

# Mettre à jour les dépendances majeures (avec prudence)
npm outdated
npm update

9.5 — Audit de sécurité

Effectuez un audit de sécurité trimestriel :

  • Vérification des dépendances avec npm audit
  • Revue des accès à la base de données
  • Test des endpoints API non authentifiés
  • Vérification des en-têtes HTTP de sécurité
  • Revue des logs pour activités suspectes

🌐 Déploiement

10.1 — Option 1 : Vercel + Railway + Supabase

Frontend — Vercel

Connectez le dépôt GitHub. Le framework Next.js est détecté automatiquement. Le build se lance à chaque push sur main.

Backend — Railway

Créez un projet Railway, connectez le dépôt. Spécifiez la commande de démarrage : node apps/backend/dist/index.js.

Base de données — Supabase

Créez un projet Supabase, puis une base PostgreSQL. Utilisez la connexion fournie pour DATABASE_URL.

10.2 — Option 2 : Docker

Utilisez le fichier docker-compose.yml fourni dans les annexes :

docker-compose up -d --build

Cette commande lance le backend, le frontend et la base de données PostgreSQL dans des conteneurs isolés.

10.3 — Option 3 : VPS avec PM2

# Installer PM2
npm install -g pm2

# Build du projet
npm run build

# Démarrer avec PM2
pm2 start apps/backend/dist/index.js --name jetlingo-api

# Sauvegarder la configuration PM2
pm2 save

# Démarrage automatique au boot
pm2 startup

🛠️ Dépannage

Problème Solution
Cannot connect to database Vérifier la variable DATABASE_URL, s'assurer que PostgreSQL est en marche et que l'utilisateur jetlingo existe avec les droits appropriés.
OpenAI API error: 401 Unauthorized Vérifier que la variable OPENAI_API_KEY est correcte et que le compte OpenAI a un solde suffisant.
OpenAI API error: 429 Rate Limited Attendre le délai indiqué dans les en-têtes Retry-After. Envisager de mettre en place un rate limiting côté application.
JWT verification failed Vérifier que le JWT_SECRET dans le fichier .env correspond à celui utilisé lors de la génération du token. Si le secret a changé, les utilisateurs doivent se reconnecter.
Port already in use Modifier la variable PORT dans le fichier .env ou arrêter le processus utilisant ce port : lsof -i :4000
Seed échoue Vérifier que le schéma a bien été poussé avec npx drizzle-kit push avant d'exécuter npm run seed.
Module not found Supprimer node_modules et le fichier package-lock.json, puis relancer npm install.
ECONNREFUSED sur Redis Vérifier que Redis est démarré. Si Redis n'est pas nécessaire, retirez REDIS_URL du fichier .env.
CORS error côté navigateur Ajouter l'origine du frontend dans la variable CORS_ORIGIN du fichier .env.
TypeError: Cannot read properties of undefined Vérifier que toutes les variables d'environnement requises sont définies dans le fichier .env.
